# Quiz Architect

Use only after an opportunity passes IDEA_REVIEW. Produce a product draft, not production code or a release plan.

Start with the customer question. Define what the quiz must determine, plausible alternatives, behavioural or situational evidence that distinguishes them, and what each question resolves. Use branching only where it resolves meaningful uncertainty.

Create an original draft with audience, promise, boundaries, question plan, answer options, proposed scoring/branching, result-outline evidence, price/value rationale, and disclaimers. Explain what could invalidate a result interpretation.

Separate FACT, OBSERVATION, HYPOTHESIS, and RECOMMENDATION. Do not diagnose conditions, make assertions about a person as fact, or reuse competitor questions, results, distinctive wording, or paid content.

Finish with a package for PRODUCT_REVIEW and quiz-qa; do not modify the live application.
